# Proposal: MOODISM Identity and Layering

**Proposal ID:** MIP-CANON-001  
**Status:** Accepted for Canon v0.2  
**Accepted by:** Repository maintainer  
**Acceptance basis:** Explicit instruction to proceed with the proposed repository direction  
**Date:** 2026-09-02  
**Scope:** Identity, authority, naming, and layer boundaries

## Summary

This proposal establishes MOODISM as the civilizational philosophy of the
MOOD world while preserving MOOD as the independent project and repository.
It distinguishes the worldview, the world, the protocol, economic
instruments, applications, and the website so that none can silently define
all the others.

## Accepted relationship

```text
MOODISM
Civilizational philosophy and direction
        ↓
MOOD
Open coordination world and independent project
        ↓
MOOD Protocol
Institutional and technical rules
        ↓
Economy
Optional, downstream coordination instruments
        ↓
Applications
Independent participants, including Moodify
```

The public shorthand is:

```text
MOODISM = Why
MOOD = World and project
MOOD Protocol = How
MOOD economic instruments = Downstream coordination tools
Moodify = An application, not the constitutional center
Website = An entrance, not the world
```

## Canon changes authorized

1. Define MOODISM as a contribution-driven vision of network civilization.
2. State that MOOD is the open world and project through which that vision is
   explored.
3. Distinguish MOOD Protocol from MOOD as a whole.
4. Treat any token as downstream of contribution, proof, reputation, rights,
   responsibility, and explicit economic authorization.
5. Preserve MOOD as the repository and public project name.
6. Preserve Moodify only as an application or compatibility boundary.

## What this proposal does not authorize

- It does not activate token rewards, staking, governance, treasury,
  distribution, liquidity, or settlement.
- It does not declare an existing Moodify-named contract to be the final
  native economic instrument of MOOD.
- It does not grant governance or economic rights solely from token ownership.
- It does not convert draft protocol code into production infrastructure.
- It does not make AI agents constitutional authorities.

## Existing implementation status

Existing website routes, protocol modules, contracts, schemas, and operational
documents are implementation evidence. They remain subject to review against
Canon v0.2. No existing code gains authority merely because this proposal is
accepted.

## Migration

1. Amend `MOOD_CANON.md` to v0.2.
2. Publish the Chinese and English editions of MOODISM Manifesto 001 as
   Genesis Drafts under `docs/manifesto/`.
3. Create a bilingual lexicon for identity-critical terms.
4. Update repository and documentation navigation.
5. Audit website, protocol, token, and treasury claims in later changes.

## Unresolved questions

- The final role and name of the existing Moodify-named token contract.
- Formal contribution verification and appeals.
- The boundary between reputation, rights, and economic interests.
- Machine-agent accountability and identity.
- Legitimate governance and treasury activation conditions.

These questions remain unresolved by design. They require their own authority
documents before implementation may become permanent.
