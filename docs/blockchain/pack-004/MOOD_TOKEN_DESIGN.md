# MOOD Token Design

## Purpose

Define the role of MOOD Token inside the network.

---

Token functions may include:

- incentives
- settlement
- ecosystem participation
- governance support

---

Important Principle:

Token value should come from network activity.

Network activity should not be created only for token value.

---

> **No token is asserted as live.** Specifically, none of the
> following are claimed: token name, symbol, decimals, total supply,
> circulating supply, mint authority, burn authority, transfer
> restrictions, listing venue, or distribution schedule.
>
> Per `MOOD_CANON.md` §12, the token is downstream of meaning. The
> token does not precede the protocol, the culture, or the canon.
> Token activation requires (a) an authoritative specification,
> (b) Canon alignment review, (c) explicit human approval per
> Canon §Safety.
>
> This document captures role-direction only. It is not a tokenomics
> paper and must not be cited as one.

## Role-Direction Boundaries

- Token is for **coordination**, not speculation.
- Token value **emerges from network activity**, not the reverse.
- Token activation is **downstream** of the protocol and the canon.
- Token governance is **not** a substitute for canonical governance.
