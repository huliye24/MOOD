# MOOD Contribution Policy

Contribution is the foundation of MOOD.

Examples:

## Technical Contribution

- code
- architecture
- security
- infrastructure

## Creative Contribution

- design
- content
- culture

## Resource Contribution

- compute
- data
- capital

## Ecosystem Contribution

- community
- partnerships
- education

All contributions should be documented and verifiable.

---

> This policy enumerates types of contribution. It does not define how
> contributions are recorded, weighted, rewarded, or tokenized. Those
> questions belong to:
>
> - `docs/architecture/05_contribution-proof.md` (proof categories)
> - `docs/architecture/06_reputation-engine.md` (reputation model)
> - `docs/architecture/02_protocol-architecture.md` §3 (placement)
>
> All of the above remain at the conceptual stage. No live contribution
> recording, weighting, or reward mechanism is asserted by this
> document.

## Canon Alignment

- **§5 Markdown as Canonical Memory:** Contribution categories are
  recorded as readable Markdown, not opaque scoring.
- **§8 Code Must Earn the Right to Exist:** No implementation is
  implied by listing a contribution category.
- **§14 Canonical change:** Adding or removing a contribution category
  is a constitutional amendment, not a local edit.
