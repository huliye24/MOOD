# 023 — Staging Data Policy

**Date:** 2026-08-30

## Core Rule

Staging data MUST be isolated from production data.

## Allowed Data Sources

1. **Synthetic data** — generated by seed scripts.
2. **Explicitly safe test data** — values that do not exist in production.
3. **Public / non-sensitive migrated samples** — e.g., public MIP drafts.

## Forbidden Data Sources

- Production Treasury balances
- Production Resident PII (email, etc.)
- Real Genesis airdrop allocations
- Production support_intents / payment records
- Production API keys / RPC credentials

## Seed Strategy

Staging seed should include:

```text
- 1 staging MIP draft (MIP-STAGING-001)
- 1 staging Contribution Task (STAGING-TASK-001)
- 1 staging Resident (test wallet)
- 1 staging Agent (status=registered)
- 1 staging Node (status=draft)
- Empty Treasury (default inactive)
- Empty Governance history
```

## Cleanup Strategy

```bash
# Environment-guarded cleanup script
MOOD_ENV=staging npm run staging:cleanup
```

Cleanup script MUST refuse to run if:

- `MOOD_ENV !== "staging"`
- `MOOD_LAUNCH_STATE !== "staging"`
- `DATABASE_URL` matches production pattern

## Migration Compatibility

- Migrations apply identically to staging and production.
- No data migrations in 023 (schema only).
- Migration version recorded in deployment log.
